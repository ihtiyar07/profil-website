PostgreSQL çekirdeğinin bellek yönetimi, 8KB data page anatomisi, tuple görünürlüğü ve bloat analizleri incelenirken standart sistem katalogları (`pg_stat_activity`, `pg_stat_user_tables`) tek başına yeterli olmaz. Çekirdek kaynak ağacında (`contrib`) yer alan yerleşik teşhis eklentileri, fiziksel depolama ve paylaşımlı bellek katmanlarını doğrudan sorgulanabilir hale getirir.

Ancak bu araçların **canlı production sistemlerinde** gelişigüzel çalıştırılması disk I/O sıçramalarına veya bellek içi kilit (`LWLock`) çekişmelerine yol açabilir.

---

## 1. Teşhis ve Operasyon Eklentileri Matrisi

| Eklenti | Yükleme Yöntemi | Production Riski / Maliyeti | Ne Zaman Kullanılır? |
| :--- | :--- | :--- | :--- |
| **`pg_stat_statements`** | `shared_preload_libraries` (**Restart Gerekir**) | Düşük (Hash table boyutu kadar sabit RAM + hafif hook maliyeti) | En yavaş, en çok CPU veya `temp_blks_written` (Spill to Disk) üreten sorguları bulma |
| **`pg_buffercache`** | On-Demand (`CREATE EXTENSION`) | **Orta-Yüksek (`BufMappingLock` / `LWLock` alır)** | `shared_buffers` içinde hangi tablo/indeksin kaç KB yer tuttuğunu ve `usagecount` durumunu izleme |
| **`pageinspect`** | On-Demand (`CREATE EXTENSION`) | Düşük-Orta (Yalnızca istenen 8KB sayfayı okur; `superuser` gerektirir) | Ham data page header (`pd_lower`/`pd_upper`), line pointer, `t_xmin`/`t_xmax` ve B-Tree analizleri |
| **`pgstattuple`** | On-Demand (`CREATE EXTENSION`) | **Yüksek** (`pgstattuple()` tüm tabloyu `Seq Scan` ile tarar; `pgstattuple_approx()` hafif çalışır) | Gerçek ölü satır (`dead_tuple_percent`) ve silinmiş boş alan (`free_percent`) oranını ölçme |
| **`pg_repack`** | Harici Paket + `CREATE EXTENSION` | Düşük (Arka planda log tablosu tutar; yalnızca son `swap` anında milisaniyelik `AccessExclusiveLock` alır) | `VACUUM FULL` gibi tabloyu kilitlemeden şişmiş tablo ve indeksleri online küçültme |

## 2. Production Güvenlik Kuralları

- **Tam Tarama Yerine `pgstattuple_approx()`:** Terabayt seviyesindeki tablolarda standart `pgstattuple('tablo')` fonksiyonu tüm veri dosyalarını baştan sona okuyarak I/O kuyruğunu boğar. Bunun yerine **Visibility Map (VM)** üzerinden all-visible sayfaları atlayarak tahmin üreten `pgstattuple_approx()` kullanılmalıdır.
- **`pg_buffercache` Sıklığı:** Her saniye `pg_buffercache` görünümünü sorgulayan monitoring scriptleri `shared_buffers` içerisindeki bellek haritası kilitlerini (`LWLock`) meşgul edebilir; yalnızca anomali teşhisinde veya seyrek aralıklarla çalıştırılmalıdır.

## 3. Laboratuvar: `pg_stat_statements` ve `pgstattuple_approx`

İzole ortamda `shared_preload_libraries = 'pg_stat_statements'` yapılandırmasıyla sorgu normalizasyonunu ve yaklaşık bloat ölçümünü test edelim:

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
CREATE EXTENSION IF NOT EXISTS pgstattuple;

CREATE TABLE ext_demo (id int PRIMARY KEY, data text);
INSERT INTO ext_demo SELECT g, repeat('z', 100) FROM generate_series(1, 50000) g;
DELETE FROM ext_demo WHERE id <= 20000;

-- 1. En çok bellek vuruşu (hit) ve süre tüketen normalize sorgular:
SELECT calls, round(total_exec_time::numeric, 2) AS total_ms,
       shared_blks_hit, temp_blks_written, left(query, 45) AS query_sample
FROM pg_stat_statements
WHERE query LIKE '%ext_demo%'
ORDER BY total_exec_time DESC LIMIT 3;
```

```text
 calls | total_ms | shared_blks_hit | temp_blks_written |                 query_sample                  
-------+----------+-----------------+-------------------+-----------------------------------------------
     1 |    65.93 |          151466 |                 0 | INSERT INTO ext_demo SELECT g, repeat($1, $2)
     1 |     9.80 |           20401 |                 0 | DELETE FROM ext_demo WHERE id <= $1
     1 |     2.61 |             456 |                 0 | CREATE TABLE ext_demo (id int PRIMARY KEY, da
(3 rows)
```

```sql
-- 2. Tüm tabloyu taramadan hızlı bloat tahmini (Visibility Map destekli):
SELECT approx_tuple_count, approx_tuple_percent, approx_free_percent, dead_tuple_percent
FROM pgstattuple_approx('ext_demo');
```

```text
 approx_tuple_count | approx_tuple_percent | approx_free_percent | dead_tuple_percent 
--------------------+----------------------+---------------------+--------------------
              30000 |    54.74068474797219 |  0.6440446661355735 |  36.49378983198146
(1 row)
```
