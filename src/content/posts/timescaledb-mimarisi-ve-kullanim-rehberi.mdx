**TimescaleDB**, standart PostgreSQL üzerine eklenti (extension) olarak çalışan açık kaynaklı bir zaman serisi veritabanıdır. Yüksek frekanslı sensör, log veya finansal veriler yüz milyonlarca satıra ulaştığında standart B-Tree indeksleri `shared_buffers` alanına sığmaz ve disk I/O darboğazı başlar. TimescaleDB bu sorunu veriyi zaman aralıklarına göre otomatik alt tablolara (**Chunk**) bölerek çözer.

## 1. Docker ile Hızlı Kurulum

PostgreSQL 16 tabanlı resmi TimescaleDB imajını tek komutla ayağa kaldırıp eklentiyi aktif edebilirsiniz:

```bash
docker run -d --name timescaledb \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=secretpassword \
  -v timescaledb_data:/var/lib/postgresql/data \
  timescale/timescaledb:latest-pg16
```

Konteyner içindeki `psql` istemcisine bağlanıp eklentiyi etkinleştirin:

```bash
docker exec -it timescaledb psql -U postgres
```

```sql
CREATE EXTENSION IF NOT EXISTS timescaledb CASCADE;
```

## 2. Case Senaryosu ve 10M Satır Veri Üretimi

Farkı ölçmek için 100 farklı IoT cihazından 30 gün boyunca gelen CPU ve sıcaklık ölçümlerini simüle edelim. Aynı 10 milyon satırlık veriyi hem standart PostgreSQL tablosuna hem de TimescaleDB Hypertable'a yükleyelim.

```sql
-- 1. Standart PostgreSQL Tablosu
CREATE TABLE sensor_data_std (
    time        TIMESTAMPTZ NOT NULL,
    device_id   INT NOT NULL,
    cpu_usage   DOUBLE PRECISION,
    temperature DOUBLE PRECISION
);
CREATE INDEX idx_std_device_time ON sensor_data_std (device_id, time DESC);

-- 2. TimescaleDB Hypertable (1 günlük chunk aralığı)
CREATE TABLE sensor_data_ts (
    time        TIMESTAMPTZ NOT NULL,
    device_id   INT NOT NULL,
    cpu_usage   DOUBLE PRECISION,
    temperature DOUBLE PRECISION
);
SELECT create_hypertable('sensor_data_ts', 'time', chunk_time_interval => INTERVAL '1 day');
CREATE INDEX idx_ts_device_time ON sensor_data_ts (device_id, time DESC);

-- 3. 10.000.000 Satır Sentetik Veri Basma (~259ms aralıklarla 30 gün)
INSERT INTO sensor_data_std (time, device_id, cpu_usage, temperature)
SELECT
    t,
    (random() * 99 + 1)::INT,
    random() * 100.0,
    20.0 + (random() * 45.0)
FROM generate_series(
    NOW() - INTERVAL '30 days',
    NOW(),
    INTERVAL '259 milliseconds'
) AS t;

INSERT INTO sensor_data_ts SELECT * FROM sensor_data_std;
```

EXPLAIN (ANALYZE, BUFFERS)
SELECT AVG(temperature), MAX(cpu_usage)
FROM sensor_data_ts
WHERE device_id = 42
  AND time >= NOW() - INTERVAL '2 days'
  AND time <  NOW() - INTERVAL '1 day';

## 4. İleri Seviye Analitik Fonksiyonlar

TimescaleDB, standart SQL'de yazılması karmaşık veya performanssız olan zaman serisi analizleri için özel C fonksiyonları sunar.

### A. `time_bucket()`: Esnek Zaman Pencereleri
Standart `date_trunc` yalnızca sabit birimlerle (saat, gün) çalışırken; `time_bucket` ile 5 dakika, 15 dakika veya 4 saat gibi keyfi aralıklar oluşturulur:

```sql
SELECT
    time_bucket('15 minutes', time) AS bucket,
    device_id,
    ROUND(AVG(temperature)::NUMERIC, 2) AS avg_temp,
    MAX(cpu_usage) AS peak_cpu
FROM sensor_data_ts
WHERE time >= NOW() - INTERVAL '24 hours' AND device_id = 42
GROUP BY bucket, device_id
ORDER BY bucket DESC;
```

### B. `time_bucket_gapfill()`, `locf()` ve `interpolate()`
Ağ kesintisi veya sensör yeniden başlatma anlarında seride boş zaman aralıkları (gaps) oluşur. `time_bucket_gapfill` bu eksik zaman dilimlerini otomatik üretir; `locf` (Last Observation Carried Forward) son bilinen değeri taşır, `interpolate` ise doğrusal ara değer hesaplar:

```sql
SELECT
    time_bucket_gapfill('10 minutes', time) AS bucket,
    device_id,
    AVG(temperature)              AS raw_avg,
    locf(AVG(temperature))        AS temp_locf,
    interpolate(AVG(temperature)) AS temp_linear_interp
FROM sensor_data_ts
WHERE time >= NOW() - INTERVAL '6 hours'
  AND time <= NOW()
  AND device_id = 42
GROUP BY bucket, device_id
ORDER BY bucket;
```

### C. Continuous Aggregates (Artımlı Özet Tablolar)
Büyük tarih aralıklarında her seferinde milyonlarca ham satırı toplamak yerine arka planda artımlı güncellenen özet görünümler kullanılır:

```sql
CREATE MATERIALIZED VIEW sensor_hourly_summary
WITH (timescaledb.continuous) AS
SELECT
    time_bucket('1 hour', time) AS bucket,
    device_id,
    AVG(temperature) AS avg_temp,
    MAX(cpu_usage)   AS max_cpu,
    COUNT(*)         AS sample_count
FROM sensor_data_ts
GROUP BY bucket, device_id;

SELECT add_continuous_aggregate_policy('sensor_hourly_summary',
    start_offset      => INTERVAL '3 days',
    end_offset        => INTERVAL '1 hour',
    schedule_interval => INTERVAL '15 minutes');
```

### D. Native Columnar Sıkıştırma ve Retention Politikası
Aktif yazma penceresinden çıkan eski chunk'lar sütunsal (columnar) formata dönüştürülüp sıkıştırılır, saklama süresi dolanlar ise `DELETE` maliyeti olmadan diskten düşürülür:

```sql
ALTER TABLE sensor_data_ts SET (
    timescaledb.compress,
    timescaledb.compress_segmentby = 'device_id',
    timescaledb.compress_orderby   = 'time DESC'
);

-- 7 günden eski chunk'ları sıkıştır, 90 günden eskileri sil
SELECT add_compression_policy('sensor_data_ts', INTERVAL '7 days');
SELECT add_retention_policy('sensor_data_ts', INTERVAL '90 days');
```
