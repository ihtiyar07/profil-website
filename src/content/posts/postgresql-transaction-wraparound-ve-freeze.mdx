PostgreSQL'in MVCC mekanizması transaksiyon kimlikleri (**XID**) üzerine kuruludur. Ancak çekirdekteki XID sayacı **32-bit işaretsiz bir tamsayıdır** (`2^32 ≈ 4.29 milyar` transaksiyon).

Bu sayaç dairesel aritmetik (**Modulo 2^32**) ile çalışır: Herhangi bir XID için önceki 2 milyar işlem "geçmiş", sonraki 2 milyar işlem ise "gelecek" kabul edilir. Eğer veritabanı 2 milyardan fazla işlem görür ve eski satırlar dondurulmazsa (**Freeze**), eski veriler birden geleceğe aitmiş gibi görünerek **aniden tüm tablolardan kaybolur!**

---

## 1. Dairesel Aritmetik ve Freeze Çözümü

PostgreSQL bu felaketi önlemek için satırları **dondurur (Freeze)**:

1. Bir satırın `t_xmin` yaşı **`vacuum_freeze_min_age`** (varsayılan: 50 milyon) değerini aştığında, `VACUUM` bu satırın başlığına **`HEAP_XMIN_FROZEN`** bayrağını yazar.
2. Dondurulan bir satır artık spesifik bir XID ile karşılaştırılmaz; sistemdeki tüm aktif ve gelecekteki transaksiyonlardan daha eski olduğu kabul edilir.
3. Böylece 32-bit sayaç dönüp başa gelse dahi donmuş satırlar asla görünmezlik tehlikesi yaşamaz.

## 2. Wraparound Riski Nasıl İzlenir?

Bir veritabanındaki en yaşlı dondurulmamış işlem `pg_database.datfrozenxid` alanında tutulur:

```sql
SELECT datname,
       age(datfrozenxid) AS xid_age,
       2147483648 - age(datfrozenxid) AS remaining_xid,
       round(100.0 * age(datfrozenxid) / 2147483648, 2) AS wraparound_risk_pct
FROM pg_database
ORDER BY xid_age DESC;
```

Eğer `xid_age` değeri **200 milyonu (`autovacuum_freeze_max_age`)** aşarsa Postgres sistemi korumak için zorunlu agresif autovacuum başlatır.

---

## 3. Acil Durum Prosedürü: Sistem Kilitlenirse Ne Yapılır?

Eğer limit 2 milyara yaklaşırsa (son 3 milyon XID kaldığında), PostgreSQL veritabanını **salt okunur (read-only)** moda alır ve yeni hiçbir yazma/transaksiyon kabul etmez:
```text
PANIC: could not locate a valid checkpoint record
FATAL: database is not accepting commands to avoid wraparound data loss in database "postgres"
HINT: Stop the postmaster and vacuum that database in single-user mode.
```

### Acil Kurtarma Adımları (Single-User Mode):
1. PostgreSQL servisini durdurun:
   ```bash
   systemctl stop postgresql
   ```
2. Tek kullanıcılı modda arka plan süreçleri olmadan doğrudan cluster'ı başlatın:
   ```bash
   postgres --single -D /var/lib/postgresql/data postgres
   ```
3. Tekil konsolda zorunlu freeze çalıştırın:
   ```sql
   VACUUM FREEZE VERBOSE;
   ```
4. İşlem bitince `Ctrl+D` ile çıkıp normal servisi başlatın:
   ```bash
   systemctl start postgresql
   ```

## 4. Laboratuvar: Freeze Operasyonunu Gözlemleme

```sql
-- Mevcut veritabanının XID yaşını kontrol edelim:
SELECT age(datfrozenxid) FROM pg_database WHERE datname = current_database();

-- Belirli bir tabloda tüm satırları hemen donduralım:
VACUUM (FREEZE, VERBOSE) bloat_test;
```

Bu komut sayesinde tablodaki tüm eski satırlar `HEAP_XMIN_FROZEN` ile mühürlenir ve tablonun XID yaşı sıfırlanır.
