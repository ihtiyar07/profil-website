PostgreSQL ikili dosyalarının sisteme hangi kaynaktan kurulduğu bakım kolaylığını, `initdb` aşamasında verilen parametreler ise veritabanı kümesinin yaşam boyu karakter setini ve veri bütünlüğü garantisini belirler.

---

## 1. Paket Kurulumu: `apt` ve `dnf` (PGDG Resmi Deposu)

İşletim sistemlerinin kendi depoları (`AppStream` veya Debian `stable`) genellikle tek ve görece eski bir PostgreSQL sürümü sunar. Güncel major sürümleri (ör. PostgreSQL 17/18) ve aynı sunucuda paralel kurulum araçlarını almak için **PGDG (PostgreSQL Global Development Group)** deposu kullanılır:

```bash
# Debian / Ubuntu (PGDG APT Deposu)
sudo install -d /usr/share/postgresql-common/pgdg
curl -fsSL https://www.postgresql.org/media/keys/ACCC4CF8.asc \
  | sudo gpg --dearmor -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.gpg
echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.gpg] \
  https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" \
  | sudo tee /etc/apt/sources.list.d/pgdg.list
sudo apt-get update && sudo apt-get install -y postgresql-17
```

**RHEL / Rocky / AlmaLinux (EL9)** tarafında ise işletim sisteminin yerleşik eski modülü devre dışı bırakılmadan PGDG paketleri çakışır:

```bash
sudo dnf install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm
sudo dnf -qy module disable postgresql
sudo dnf install -y postgresql18-server postgresql18-contrib
sudo /usr/pgsql-18/bin/postgresql-18-setup initdb
```

## 2. Kaynak Koddan Derleme ve Docker Seçenekleri

### Kaynak Koddan Derleme (`configure` & `meson`)

Standart paketlerde bulunmayan çekirdek yamaları, farklı sayfa boyutu (`--with-blocksize`) veya spesifik derleyici optimizasyonu gerektiğinde PostgreSQL kaynak koddan derlenir. Modern PostgreSQL sürümlerinde klasik `autotools` yanında daha hızlı olan **`meson` + `ninja`** altyapısı da desteklenir.

Buradaki `./configure` komutu **derleme zamanı yapılandırmasıdır (build-time)**; C ikili dosyalarına hangi paylaşımlı kütüphanelerin (`ICU`, `OpenSSL`, `lz4`, `systemd`, `liburing`) bağlanacağını belirler. Veritabanı kümesini (`$PGDATA`) veya çalışma zamanı ayarlarını (`postgresql.conf`) kurmaz:

```bash
# 1. Derleme Zamanı Yapılandırması ve İkili Dosyaların Kurulumu
./configure \
  --prefix=/opt/pg18 \
  --with-icu \
  --with-openssl \
  --with-lz4 \
  --with-zstd \
  --with-systemd
make -j$(nproc) && sudo make install
```

> Derlenmiş bir PostgreSQL ikilisinin hangi derleme bayraklarıyla üretildiğini doğrulamak için `/opt/pg18/bin/pg_config --configure` komutu kullanılır.

### Derleme Sonrası: Sistem Kullanıcısı, Dizin İzinleri ve `initdb`

İkili dosyalar (`bin/`, `lib/`) sisteme kurulduktan sonra veritabanının çalışabilmesi için işletim sistemi kullanıcısı ve `$PGDATA` kümesinin oluşturulması şarttır (`postgres` kullanıcısı `root` olarak çalıştırılamaz):

```bash
# 2. Sistem Kullanıcısı ve Dizinlerin Hazırlanması
sudo useradd -r -m -d /var/lib/pgsql -s /bin/bash postgres
sudo mkdir -p /var/lib/pgsql/18/data /var/lib/pgsql/18/wal
sudo chown -R postgres:postgres /var/lib/pgsql

# 3. initdb ile Veritabanı Kümesinin (Cluster) Başlatılması
sudo -u postgres /opt/pg18/bin/initdb \
  -D /var/lib/pgsql/18/data \
  --waldir=/var/lib/pgsql/18/wal \
  --encoding=UTF8 \
  --locale-provider=icu \
  --icu-locale=tr-TR \
  --data-checksums
```

`initdb` çalıştırıldığında disk üzerinde sistem tabloları ve şablon veritabanları oluşturulup başarıyla mühürlenir:

```text

This user must also own the server process.

Using language tag "tr-TR" for ICU locale "tr-TR".
The database cluster will be initialized with this locale configuration:
  locale provider:   icu
  default collation: tr-TR
The default database encoding has accordingly been set to "UTF8".
Data page checksums are enabled.

creating subdirectories ... ok
selecting dynamic shared memory implementation ... posix
creating configuration files ... ok
running bootstrap script ... ok
syncing data to disk ... ok

Success. You can now start the database server using:
    /opt/pg18/bin/pg_ctl -D /var/lib/pgsql/18/data -l logfile start
```

### Konfigürasyon Sırası: `initdb` Öncesi mi, Sonrası mı?

Veritabanı parametreleri mimaride iki ayrı aşamada yönetilir:

1. **`initdb` Anında Sabitlenenler (Geri Dönüşsüz):** Karakter seti (`--encoding=UTF8`), dil sıralayıcısı (`--locale-provider=icu`), veri blok mühürleri (`--data-checksums`) ve fiziksel WAL yolu (`--waldir`). Bunlar veritabanı oluştuktan sonra `postgresql.conf` üzerinden değiştirilemez; değişim yeni bir `initdb` ve mantıksal veri aktarımı (`pg_dump`) ister.
2. **`initdb` Sonrası Yapılandırılanlar (Esnek Çalışma Zamanı):** `initdb` tamamlandığında `$PGDATA/postgresql.conf` ve `pg_hba.conf` dosyaları varsayılan güvenli ayarlarla diskte hazırdır. DBA bu aşamada iki yöntem seçebilir:
   - **Başlatmadan Önce Yapılandırma:** `$PGDATA/postgresql.conf` doğrudan metin editörüyle açılır; `shared_buffers`, `max_connections`, `port` ve `listen_addresses` düzenlenip servis ilk kez öyle ayağa kaldırılır.
   - **Önce Başlatıp Canlıda Yapılandırma:** Veritabanı doğrudan `pg_ctl start` ile başlatılır. Ardından SQL istemcisi üzerinden `ALTER SYSTEM SET shared_buffers = '4GB';` veya `ALTER SYSTEM SET work_mem = '32MB';` komutlarıyla ayarlar `postgresql.auto.conf` dosyasına yazdırılır ve bağlama göre `pg_ctl reload` (SIGHUP) veya `restart` ile devreye alınır.
   - **`initdb -c` ile Varsayılanları Ezme:** `initdb` çalıştırılırken doğrudan `-c shared_buffers=2GB -c work_mem=64MB` parametreleri verilerek oluşturulan ilk `postgresql.conf` dosyasının bu değerlerle yazılması da mümkündür.

```bash
# 4. Servisi Başlatma ve Canlıda Konfigüre Etme Örneği
sudo -u postgres /opt/pg18/bin/pg_ctl -D /var/lib/pgsql/18/data -l /var/lib/pgsql/18/logfile start

# Başlatıldıktan sonra SQL üzerinden yapılandırma:
sudo -u postgres /opt/pg18/bin/psql -c "ALTER SYSTEM SET shared_buffers = '4GB';"
sudo -u postgres /opt/pg18/bin/psql -c "ALTER SYSTEM SET work_mem = '32MB';"
sudo -u postgres /opt/pg18/bin/pg_ctl -D /var/lib/pgsql/18/data restart
```

### Docker / Container Kurulumu

Container yapısı geliştirme, CI testleri ve Kubernetes operatörleri (`CloudNativePG`) için yüksek tekrarlanabilirlik sunar; ancak klasik VM/bare-metal dışındaki 4 sınıra dikkat edilmelidir:

1. **Paylaşımlı Bellek (`--shm-size`):** Docker varsayılan olarak `/dev/shm` alanını 64MB ile sınırlar. `shared_buffers` büyük ayarlanmasa bile paralel sorgu çalışanları (`dynamic_shared_memory_type = posix`) için `--shm-size=256m` veya üzeri verilmelidir.
2. **Sürüm Dizin Yapısı ve İzinler:** Resmi PostgreSQL 18 imajında `PGDATA` yolu `/var/lib/postgresql/18/docker` biçiminde sürüme bağlanmıştır; bind mount edilen dizinin container içi `postgres` UID/GID'sine yazılabilir olması gerekir.
3. **PID 1 ve Sinyal İletimi:** Container içinde başlangıç script'i `exec postgres` ile kendini değiştirmeli ve orchestrator'ün `stop_timeout` süresi uzun checkpoint'leri kesmemelidir.

### `Data Checksums` Maliyeti ve Doğrulanması

`--data-checksums` açıldığında PostgreSQL her 8KB `Data Page` diske yazılmadan hemen önce 16-bit bir checksum değeri hesaplar ve sayfa başlığına yazar; sayfa `Buffer Pool`'a geri okunduğunda bu değer doğrulanır.

* **Maliyet:** Modern x86_64 işlemcilerde CPU ek yükü genellikle **~%1–2** bandındadır.
* **Kazanç:** RAID denetleyicisi veya disk katmanından sızan sessiz blok bozulmalarını (`silent data corruption`) veri çoğalmadan okuma anında yakalar.
* **Kurulum Sonrası Kontrol:** Checksum aktif edilmemiş bir kümede sonradan açmak (`pg_checksums --enable`) için sunucunun tamamen durdurulması gerekir. Durmuş bir kümede bütünlüğü taramak için `--check` komutu kullanılır:

```text
# pg_checksums --check -D /var/lib/postgresql/18/data
Checksum operation completed
Files scanned:   950
Blocks scanned:  2884
Bad checksums:  0
Data checksum version: 1
```
