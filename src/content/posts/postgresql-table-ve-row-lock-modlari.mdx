PostgreSQL'de veritabanı nesneleri üzerinde işlem yapılırken hem tablo hem de satır düzeyinde koruma sağlanır. Bir sorgu çalıştığında önce ilgili tablo üzerinde uygun bir **Table-Level Lock**, ardından gerekiyorsa satırlar üzerinde **Row-Level Lock** talep edilir.

---

## 1. Table-Level Lock Modları ve Çakışma Matrisi

PostgreSQL 8 farklı tablo kilit seviyesi sunar. En hafif mod `AccessShareLock`, en ağır mod ise tabloya okuma dahil tüm erişimleri kesen `AccessExclusiveLock` modudur.

| Kilit Modu | Temsil Ettiği Temel Komutlar | Çakıştığı Kilitler |
| :--- | :--- | :--- |
| **`AccessShareLock`** | `SELECT` | Yalnızca `AccessExclusiveLock` |
| **`RowShareLock`** | `SELECT FOR UPDATE`, `SELECT FOR SHARE` | `ExclusiveLock`, `AccessExclusiveLock` |
| **`RowExclusiveLock`** | `UPDATE`, `DELETE`, `INSERT` | `ShareLock` ve üzerindeki tüm kilitler |
| **`ShareUpdateExclusiveLock`** | `VACUUM` (standart), `ANALYZE`, `CREATE INDEX CONCURRENTLY` | Kendisi dahil `ShareUpdateExclusive` ve üzeri |
| **`ShareLock`** | `CREATE INDEX` (standart) | `RowExclusive`, `ShareUpdateExclusive` ve üzeri |
| **`ShareRowExclusiveLock`** | `CREATE TRIGGER`, bazı `ALTER TABLE` | `RowExclusive` ve üzeri tüm kilitler |
| **`ExclusiveLock`** | `REFRESH MATERIALIZED VIEW CONCURRENTLY` | `RowShare` ve üzeri tüm kilitler |
| **`AccessExclusiveLock`** | `DROP TABLE`, `TRUNCATE`, `VACUUM FULL`, `ALTER TABLE` | **TÜM** kilit modları (SELECT dahil) |

## 3. Row-Level Lock Modları

Satır kilitleri bellek yerine disk üzerindeki tuple header alanlarında (`t_infomask` ve `t_xmax`) tutulur. Dört seviye mevcuttur:

1. **`FOR UPDATE`:** Satırı silme veya birincil anahtar/benzersiz sütunu güncelleme niyeti taşır. Tüm diğer satır kilitleriyle çakışır.
2. **`FOR NO KEY UPDATE`:** Yabancı anahtar veya birincil anahtar etkilenmeyen standart sütun güncellemelerinde (`UPDATE`) çekirdek tarafından otomatik alınır. `FOR KEY SHARE` ile çakışmaz!
3. **`FOR SHARE`:** Satırın silinmesini engeller ancak başka oturumların `FOR SHARE` veya `FOR KEY SHARE` almasına izin verir.
4. **`FOR KEY SHARE`:** Bir yabancı anahtar (FK) kontrolü yapılırken referans verilen ana tablo satırında alınır. Bu sayede ana tablodaki bir satır başka bir oturum tarafından normal güncellenirken (`FOR NO KEY UPDATE`), alt tabloya yeni kayıt eklenebilir.

## 4. Laboratuvar: DDL Kilit Çatışması ve Row-Lock Davranışı

Aşağıdaki senaryoyu iki ayrı `psql` terminali açarak test edebilirsiniz.

### Adım 1: Test Tablosunu Hazırlama
```sql
CREATE TABLE accounts (
    id int PRIMARY KEY,
    owner text NOT NULL,
    balance numeric NOT NULL
);
INSERT INTO accounts VALUES (1, 'Ahmet', 1000), (2, 'Mehmet', 2500);
```

### Adım 2: Tablo Düzeyi Kilit Çakışması (AccessShare vs AccessExclusive)
```sql
-- Terminal 1: Açık bir transaksiyonda SELECT yapıp bekleyelim (AccessShareLock)
BEGIN;
SELECT * FROM accounts WHERE id = 1;
-- Transaksiyonu bilerek COMMIT etmiyoruz!

-- Terminal 2: Tabloya yeni bir sütun eklemeyi deneyelim (AccessExclusiveLock)
ALTER TABLE accounts ADD COLUMN status text DEFAULT 'active';
-- Terminal 2 ANINDA BLOKE OLUR ve Terminal 1 COMMIT/ROLLBACK yapana kadar bekler!
```

### Adım 3: Satır Seviyesi Non-Key Update Eşzamanlılığı
```sql
-- Terminal 1'de ROLLBACK yaptıktan sonra:
-- Terminal 1: Satırda FOR KEY SHARE kilidi alalım (FK kontrolü simülasyonu)
BEGIN;
SELECT * FROM accounts WHERE id = 1 FOR KEY SHARE;

-- Terminal 2: Satırın anahtar olmayan 'balance' sütununu güncelleyelim (FOR NO KEY UPDATE)
BEGIN;
UPDATE accounts SET balance = balance + 100 WHERE id = 1;
-- UPDATE BLOKE OLMADAN ANINDA BAŞARILI OLUR!
COMMIT;

-- Terminal 1:
COMMIT;
```

Bu mekanizma, PostgreSQL'in yüksek eşzamanlı OLTP sistemlerinde yabancı anahtar kontrolleri nedeniyle gereksiz kilit tıkanıklığı yaşamasını engeller.
