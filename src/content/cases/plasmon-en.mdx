## 1. Context
Plasmon was engineered for continuous monitoring and remote setpoint orchestration of industrial chillers and HVAC units in harsh factory environments. Designed for 100K+ edge devices, the architecture covers the full pipeline from physical sensor interfaces up to centralized broker ingestion.

## 2. Problem
Deployments faced two fundamental hurdles:
1. **Unreliable Cellular Coverage:** Field sites experienced frequent cellular/4G dropouts and base-station reboots. Conventional HTTP polling resulted in RAM memory exhaustion and data gaps.
2. **Bi-Directional Command & Control:** Edge units required not only passive reporting, but also dynamic setpoint adjustments, Modbus coil/holding register writing, and secure over-the-air (OTA) firmware delivery.

## 3. Architecture & Data Flow

Telemetry flows from industrial field controllers up to central persistence through four distinct architectural stages:

1. **Field Instrumentation (RS-485 / Modbus RTU):** Industrial chiller controllers, evaporators, and transducers are polled every 1000ms. Optical isolators protect the UART bus from high-voltage transients and compressor start spikes.
2. **Edge Gateway (ESP32 / FreeRTOS):** Frames are buffered in statically allocated FreeRTOS task memory. When online, frames transmit immediately over TLS; on cellular drops, data routes directly to an on-chip circular flash buffer.
3. **Transport & Network (MQTT over TLS):** Dual-path connectivity (Wi-Fi primary, 4G LTE failover) maintains a persistent QoS 1 socket. Last Will & Testament (LWT) ensures immediate notification of silent connection dropouts.
4. **Ingestion & Buffering (RabbitMQ & TimescaleDB):** Telemetry routes across topic exchanges with Dead Letter Exchanges (DLX) isolating unparseable frames while valid data streams into TimescaleDB hypertables.

## 4. Decisions & Rejected Alternatives

- **ESP32 + C (FreeRTOS) chosen, Embedded Linux rejected:** In industrial cabinets exceeding 70°C, single-board computers (Raspberry Pi) suffered SD card corruptions during abrupt power outages and drew 3W+. The ESP32 with hardware watchdog and static memory allocations provided deterministic, 24/7 reliability.
- **MQTT/TLS (QoS 1) chosen, HTTP REST rejected:** Opening TCP/TLS handshakes for every payload consumed prohibitive cellular data. A persistent MQTT socket allowed compact streaming with sub-second disconnection detection via Last Will & Testament (LWT).
- **RabbitMQ chosen for ingestion, Kafka deferred:** Per-device RPC request-reply patterns, dynamic routing keys, and lower operational complexity made RabbitMQ ideal for this workload.

## 5. Core Engineering Mechanism: Flash Ring-Buffer & Hardware Recovery

Production stability in the field rests upon two architectural defenses:

### Static Circular Ring-Buffer Architecture
On microcontrollers operating 24/7, dynamic heap allocations cause memory fragmentation, which inevitably leads to out-of-memory resets during network outages.

To guarantee bounded memory usage, a fixed-size (~320KB) circular ring-buffer was implemented on SPIFFS/LittleFS flash. Buffer memory is allocated statically at boot. During cellular carrier outages lasting up to 48 hours, telemetry frames append to circular flash blocks. Upon capacity exhaustion, the buffer wraps around and overwrites the oldest frames (FIFO), maintaining deterministic operation without heap panics. When cellular connectivity resumes, buffered frames drain chronologically to RabbitMQ without data loss.

### Transistor-Driven Hardware Modem Power Cycling
In rural industrial environments, cellular base station transitions can cause modems to hang in an unresponsive AT command state, ignoring software reset signals.

A dedicated transistor power switch controlled by an ESP32 GPIO pin was incorporated into the circuit. When the watchdog task detects no modem response for 120 seconds, it cuts DC power to the modem for 500ms, triggering a hardware cold reboot. This automated hardware failover eliminated the need for field technician dispatches.

## 6. Outcome & Measurable Results
- **Design Capacity:** Sized for 100K+ edge units concurrently publishing telemetry.
- **Verified Test Scale:** 10,000+ active sensor load simulation; p95 < 22ms broker ingest latency.
- **Cellular Outage Resilience:** During carrier downtime, the ~320KB internal flash ring-buffer maintained approximately ~48 hours of continuous frames without heap overflows, draining to RabbitMQ upon reconnect with 0 packet loss.

## 7. What I Would Do Differently
- Initially, JSON was used for device telemetry payloads. At ~180 bytes per frame, JSON caused unnecessary cellular data costs. Transitioning to Protobuf or packed binary frames from day one would have reduced bandwidth consumption by 65% upfront.
